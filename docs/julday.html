Julian Day — swe.julday()

Before you can calculate anything — planets, sunrise, ascendant — you need to give the library a time. But not in the format of "August 4, 2:30 PM". The Swiss Ephemeris uses its own time format called a Julian Day Number (JD).

Think of it as: "the number of days since January 1, 4713 BC". It's just a single floating-point number that unambiguously represents any moment in time, anywhere. Every single swe function that takes time as input expects a Julian Day.

The Function

swe.julday(year, month, day, hour, calendar) → Returns: float (the Julian Day Number)

Parameters

year : int
The year. Positive = AD, negative = BC. e.g. 2026
month : int
Month number. 1 = January, 12 = December.
day : int
Day of the month. 1 to 31.
hour : float
The hour as a decimal. This must be in UTC, not local time. Convert minutes and seconds into a fraction: hour + minute/60 + second/3600. For example, 14:30:45 UTC = 14 + 30/60 + 45/3600 = 14.5125.
calendar : int
Use swe.GREG_CAL for the Gregorian calendar (which is what we use after 1582). For dates before 1582, use swe.JUL_CAL. For our purposes, always use swe.GREG_CAL.

A Simple Example

import pysweph as swe
from datetime import datetime, timedelta

# The user's query time is 2:30 PM IST on August 4, 2026.
# IST is UTC+5:30, so we subtract 5 hours 30 minutes to get UTC.

dt_local = datetime(2026, 8, 4, 14, 30, 0)    # 2:30 PM IST
dt_utc   = dt_local - timedelta(hours=5.5)       # 9:00 AM UTC

# Build the decimal hour for swe.julday
decimal_hour = dt_utc.hour + dt_utc.minute / 60.0 + dt_utc.second / 3600.0
# decimal_hour = 9.0

jd = swe.julday(dt_utc.year, dt_utc.month, dt_utc.day, decimal_hour, swe.GREG_CAL)
print(jd)
# Output: 2461259.875  (this is the Julian Day for Aug 4, 2026 at 09:00 UTC)

The Reusable Helper Function

You'll call swe.julday() constantly, so it's cleaner to write a helper once: 

def to_jd(dt_utc: datetime) -> float:
    """Convert a UTC datetime to Julian Day Number."""
    h = dt_utc.hour + dt_utc.minute / 60.0 + dt_utc.second / 3600.0
    return swe.julday(dt_utc.year, dt_utc.month, dt_utc.day, h, swe.GREG_CAL)


def local_to_jd(dt_local: datetime, tz_offset_hours: float = 5.5) -> float:
    """Convert local time to Julian Day. Default timezone is IST (UTC+5:30)."""
    dt_utc = dt_local - timedelta(hours=tz_offset_hours)
    return to_jd(dt_utc)

Converting JD Back to a Human-Readable Time

You'll need this when converting sunrise/sunset Julian Days back into something you can display. Use swe.revjul(): 

y, m, d, h = swe.revjul(jd, swe.GREG_CAL)
# h is a decimal like 9.0 = 09:00:00 UTC

hour    = int(h)
minutes = int((h - hour) * 60)
seconds = int(((h - hour) * 60 - minutes) * 60)

# For IST, add 5:30 to UTC time
dt_utc = datetime(int(y), int(m), int(d), hour, minutes, seconds)
dt_ist = dt_utc + timedelta(hours=5.5)
print(dt_ist.strftime("%H:%M:%S IST"))

⚠️ Always use UTC

Every function in pysweph expects the Julian Day in Universal Time (UTC). If you pass IST or any other local time directly, your sunrise times will be off by 5.5 hours and all your Jamam calculations will be wrong. Always convert to UTC first.

Why does this matter for Jamakkol?

Every single Jamakkol calculation depends on an accurate Julian Day. The sunrise time, the Udhayam degree, the Mandi position — all of them are computed from a JD. If your JD is even 1 minute off, your Jamam number could be wrong, and the whole chart shifts.
