Planet Positions — swe.calc_ut()

This is the most important function in the library. You call it to find out where a planet is right now — its longitude in the zodiac, how fast it's moving, and whether it's in retrograde. Everything in Jamakkol Prasanam starts with these planetary positions.

The Function

swe.calc_ut(jd_ut, planet, flags) → Returns: (result_tuple, return_flag)

Parameters

jd_ut : float
The Julian Day in Universal Time. See Julian Day to understand how to compute this.
planet : int
Which planet you want. Use the constants below — e.g. swe.SUN, swe.MOON, etc.
flags : int
Bitmask flags that control what type of calculation to do. You'll almost always want:
swe.FLG_SWIEPH | swe.FLG_SIDEREAL | swe.FLG_SPEED

What's in the result tuple?

IndexMeaningExample
res[0]Ecliptic longitude (0°–360°)108.4521
res[1]Ecliptic latitude0.0002 (Sun is near ecliptic)
res[2]Distance from Earth (AU)1.0124
res[3]Daily speed in longitude (°/day)0.9856 (or negative = retrograde)
res[4]Daily speed in latitude0.00001
res[5]Daily speed in distance0.00001

📌 Ketu is not a separate function

Ketu is always exactly 180° opposite to Rahu. So: ketu_longitude = (rahu_longitude + 180) % 360. You never call swe.calc_ut() for Ketu — you derive it from Rahu.

Flags Explained

FlagWhat it does
swe.FLG_SWIEPHUse Swiss Ephemeris calculation method (use this always)
swe.FLG_MOSEPHUse Moshier method (alternate, slightly less accurate)
swe.FLG_SIDEREALReturn sidereal longitude (subtracts Ayanamsa automatically)
swe.FLG_SPEEDInclude daily speed in result[3]. Without this, speed is 0.

🔑 Important: FLG_SIDEREAL needs set_sid_mode first

You must call swe.set_sid_mode(swe.SIDM_LAHIRI, 0, 0) before using FLG_SIDEREAL. Otherwise the library doesn't know which ayanamsa to apply.

Example — Get All 9 Planet Positions

import pysweph as swe

swe.set_ephe_path("")
swe.set_sid_mode(swe.SIDM_LAHIRI, 0, 0)

# Combine flags: sidereal + speed
FLAGS = swe.FLG_SWIEPH | swe.FLG_SIDEREAL | swe.FLG_SPEED

PLANET_IDS = {
    "Sun"    : swe.SUN,
    "Moon"   : swe.MOON,
    "Mars"   : swe.MARS,
    "Mercury": swe.MERCURY,
    "Jupiter": swe.JUPITER,
    "Venus"  : swe.VENUS,
    "Saturn" : swe.SATURN,
    "Rahu"   : swe.TRUE_NODE,
}

def get_planets(jd: float) -> dict:
    planets = {}

    for name, pid in PLANET_IDS.items():
        res, _ = swe.calc_ut(jd, pid, FLAGS)

        lon       = res[0] % 360.0    # sidereal longitude, 0-360
        speed     = res[3]             # daily motion in degrees
        rasi      = int(lon // 30)    # which Rasi (0=Mesham...11=Meenam)
        deg_in_r  = lon % 30           # degrees within that Rasi
        retrograde = speed < 0         # negative speed = moving backwards

        planets[name] = {
            "longitude"  : round(lon, 4),
            "rasi"       : rasi,
            "deg_in_rasi": round(deg_in_r, 4),
            "speed"      : round(speed, 6),
            "retrograde" : retrograde,
        }

    # Ketu = Rahu + 180 degrees
    rahu_lon = planets["Rahu"]["longitude"]
    ketu_lon = (rahu_lon + 180) % 360
    planets["Ketu"] = {
        "longitude"  : round(ketu_lon, 4),
        "rasi"       : int(ketu_lon // 30),
        "deg_in_rasi": round(ketu_lon % 30, 4),
        "speed"      : -planets["Rahu"]["speed"],
        "retrograde" : True,  # Ketu is always retrograde
    }

    return planets


# Usage
jd = swe.julday(2026, 8, 4, 9.0)  # Aug 4, 09:00 UTC
planets = get_planets(jd)

for name, data in planets.items():
    retro_marker = " ℞" if data["retrograde"] else ""
    print(f"{name:8} → Rasi {data['rasi']+1:2}, {data['deg_in_rasi']:6.2f}°{retro_marker}")

How to read the longitude

The longitude (0°–360°) maps directly to the 12 Rasis. Since each Rasi is 30°:

Longitude → Rasi
rasi_index = int(longitude // 30) # 0 = Mesham, 1 = Rishabham … 11 = Meenam
deg_in_rasi = longitude % 30 # 0° to 29.99°
minutes = (deg_in_rasi % 1) * 60
seconds = (minutes % 1) * 60

For example: 108.45° → int(108.45 // 30) = 3 = Kadagam (Cancer), at 108.45 % 30 = 18.45° within Kadagam.

Retrograde (வக்கிரம்)

A planet is in retrograde — moving backwards — when speed < 0. This is because from Earth's perspective, when we overtake a slower outer planet in orbit, it appears to move backwards across the sky.

In Jamakkol, retrograde planets are given special significance in predictions. Always check speed < 0 in your code. Rahu and Ketu are always retrograde.
