Installation

This guide walks you through setting up pysweph and the full project structure. We'll use uv — a fast Python package manager — but plain pip works too if that's what you're used to.

Requirements

RequirementMinimum VersionNotes
Python3.10+Tested on 3.13
pysweph2.10.3.6+The Swiss Ephemeris Python wrapper
FastAPI0.100+For the API server (optional)
uvicorn0.20+ASGI server to run FastAPI

Method A — Using uv (Recommended)

If you already have a pyproject.toml file (like you do in this project), all you need to do is sync: 

# One command installs everything in pyproject.toml
uv sync

# Then add the API dependencies
uv add fastapi uvicorn python-dateutil

# Verify it's working
uv run python -c "import pysweph as swe; print('Swiss Ephemeris version:', swe.version())"

Method B — Using pip

pip install pysweph fastapi uvicorn python-dateutil

What does pysweph actually install?

When you install pysweph, you get a compiled C extension that includes a built-in Moshier ephemeris. This means you don't need to download any extra files to get started — it works out of the box with accuracy good enough for Jamakkol Prasanam.

📌 About ephemeris files

There are two modes:

  • Built-in Moshier — No files needed. Accuracy: ±1 arc-second for years 3000 BC to 3000 AD. This is enough for Jamakkol.
  • Full JPL DE431 — Download .se1 files from astro.com/swisseph. Better for very old or very future dates.

Project Structure

Here's how we recommend organizing your project: 

Jamakkol Prasanam/
├── pyproject.toml         # your dependencies
├── main.py                # FastAPI entry point
├── jamakkol_engine.py     # all calculations live here
├── constants.py           # Rasi names, Nakshatra lists
└── docs/                  # this documentation

Verify the Installation

Run this quick test to make sure everything is working:

import pysweph as swe

# Use Moshier (no files needed)
swe.set_ephe_path("")

# Set Lahiri Ayanamsa (always do this first!)
swe.set_sid_mode(swe.SIDM_LAHIRI, 0, 0)

# Get today's Julian Day
jd = swe.julday(2026, 8, 4, 9.0)  # Aug 4, 09:00 UTC

# Get the Sun's sidereal longitude
res, _ = swe.calc_ut(jd, swe.SUN, swe.FLG_SWIEPH | swe.FLG_SIDEREAL)
print(f"Sun is at {res[0]:.4f}° sidereal")
# Expected: Sun is at 108.xxxx° sidereal (Kadagam / Cancer)

If you see a number around 108°, the Sun is in Kadagam (Cancer) — which is correct for August. You're good to go.

💡 Tip

Always call swe.set_sid_mode(swe.SIDM_LAHIRI, 0, 0) at the top of your script, before any other swe function. If you forget, you'll get tropical longitudes instead of sidereal, and all your Rasi calculations will be wrong by about 24 degrees.
